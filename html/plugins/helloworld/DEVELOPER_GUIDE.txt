1. INTRODUCTION
================================================================================

The Hello World plugin is a comprehensive template demonstrating all aspects
of FlintmanCMS plugin development. It includes:

- Database table creation and management
- CRUD operations (Create, Read, Update, Delete)
- Frontend user interface
- Admin management interface
- Custom CSS styling
- JavaScript interactivity
- Smarty template integration
- Security measures
- Permission handling

This plugin serves as both a working example and a template for creating your
own custom plugins.

2. QUICK START
================================================================================

INSTALLATION:
-------------
1. Copy the entire /helloworld/ folder to /plugins/
2. Log in as administrator
3. Navigate to: admin.php?n=plugins
4. Click "Activate" next to "Hello World"
5. System will automatically:
   - Create database tables (from sql/install.sql)
   - Add menu link to navigation
   - Enable the plugin

ACCESSING THE PLUGIN:
--------------------
Frontend: index.php?n=plugins&p=helloworld
Admin:    admin.php?n=plugins&p=helloworld

TESTING:
-------
1. Visit frontend - see list of sample messages
2. Click "Add New Message" - submit a message
3. View message details
4. Access admin panel - manage messages
5. Try Edit, Delete, Settings operations

3. PLUGIN ARCHITECTURE
================================================================================

DIRECTORY STRUCTURE:
-------------------
/plugins/helloworld/
│
├── variable.php          # Plugin metadata & table definitions
├── helloworld.php        # Main frontend logic
├── README.txt            # Architecture overview
├── DEVELOPER_GUIDE.txt   # This file
├── index.html            # Security: block directory listing
│
├── /admin/
│   ├── admin.php         # Admin CRUD operations
│   └── index.html        # Security
│
├── /sql/
│   ├── install.sql       # Database schema
│   └── index.html        # Security
│
├── /template/
│   ├── page.htm          # Smarty admin template
│   └── index.html        # Security
│
├── /css/
│   ├── helloworld.css    # Plugin styles
│   └── index.html        # Security
│
└── /js/
    ├── helloworld.js     # Plugin JavaScript
    └── index.html        # Security

EXECUTION FLOW:
--------------
Frontend Access (index.php?n=plugins&p=helloworld):
1. User requests URL
2. main plugins.php checks if plugin exists
3. Loads helloworld.php
4. helloworld.php:
   - Checks permissions (authentication.php)
   - Processes actions (view, add, list)
   - Queries database
   - Builds HTML content
   - Assigns to Smarty
5. CMS renders with header/footer

Admin Access (admin.php?n=plugins&p=helloworld):
1. Admin requests URL
2. main plugin routing loads admin/admin.php
3. admin.php:
   - Checks admin authentication
   - Processes actions (add, edit, delete, settings, list)
   - Builds forms or tables
   - Assigns to Smarty
4. template/page.htm wraps content
5. CMS renders with admin layout

4. FILE-BY-FILE BREAKDOWN
================================================================================

variable.php
-----------
PURPOSE: Defines plugin metadata and database requirements
LOADED: During activation, deactivation, info display
KEY VARIABLES:
  - $plugin_db_tables: Array of table names (without prefix)
  - $plugin_name: Display name
  - $plugin_description: What the plugin does
  - $plugin_version: Version number (major.minor.patch)
  - $plugin_folder: Directory name (must match actual folder)

EXAMPLE:
  $plugin_db_tables = array("helloworld_messages", "helloworld_settings");
  $plugin_version = "1.0.0";

WHEN TO MODIFY:
  - Adding/removing database tables
  - Changing plugin name or description
  - Updating version after changes
  - Adding custom configuration variables

---

sql/install.sql
--------------
PURPOSE: Creates database tables when plugin is activated
LOADED: Automatically during first activation
SYNTAX RULES:
  - Use `flintmancms_` for table names (this is the actual DB_PREFIX)
  - End each statement with semicolon
  - Comments start with --
  - All tables must be in $plugin_db_tables array

EXAMPLE:
  CREATE TABLE `flintmancms_helloworld_messages` (
    `id` int(11) NOT NULL AUTO_INCREMENT,
    `message` varchar(255) NOT NULL,
    PRIMARY KEY (`id`)
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

TABLE DESIGN:
  - Always use AUTO_INCREMENT integer primary key named 'id'
  - Add indexes on frequently queried columns
  - Use utf8mb4 for full Unicode support
  - Provide default values where appropriate
  - Use datetime for timestamps

---

helloworld.php (Frontend)
-------------------------
PURPOSE: Handles frontend display and user interactions
URL: index.php?n=plugins&p=helloworld
STRUCTURE:
  1. Security check (IN_CMS)
  2. Load CSS/JS ($scriptAdd)
  3. Authentication check
  4. Initialize variables
  5. Process actions (view, add, list)
  6. Query database
  7. Build HTML output
  8. Assign to Smarty

COMMON PATTERNS:

Action Processing:
  if ($action == 'view') {
      // Load and display single item
  } elseif ($action == 'add') {
      if (!isset($_POST['submit'])) {
          // Show form
      } else {
          // Process form
      }
  } else {
      // Default: list all items
  }

Database Query:
  $sql = sprintf("SELECT * FROM " . DB_PREFIX . "_table WHERE id=%s",
                 quote_smart($id));
  $result = $db->sql_query($sql);
  $data = $db->sql_fetchrow($result);

Form Submission:
  $value = scrub_input($_POST['field']);
  $sql = sprintf("INSERT INTO table VALUES (%s)", quote_smart($value));
  $db->sql_query($sql);
  header("Location: redirect_url");
  exit;

---

admin/admin.php
--------------
PURPOSE: Administrative interface for CRUD operations
URL: admin.php?n=plugins&p=helloworld
STRUCTURE:
  1. Security check
  2. Admin authentication
  3. Initialize variables
  4. Process actions (add, edit, delete, settings, list)
  5. Build forms or use Report class for tables
  6. Assign to Smarty template

CRUD PATTERN:

List (default):
  - Query all records
  - Use Report class for table display
  - Include action links (edit, delete)

Add:
  - Step 1: Display empty form
  - Step 2: Process submission, redirect

Edit:
  - Step 1: Load data, display filled form
  - Step 2: Process update, redirect

Delete:
  - Step 1: Display confirmation
  - Step 2: Perform deletion, redirect

REPORT CLASS:
  $report->setMainAttributes('width="100%"');
  $report->addOutputColumn('field', 'Label', 'align', 'width');
  $report->display($data_array);
  $content = $report->showReport();

---

template/page.htm
----------------
PURPOSE: Smarty template for admin interface
VARIABLES RECEIVED:
  - {$form_action}: Where form submits
  - {$content}: HTML content from admin.php

STRUCTURE:
  {if $form_action != ''}
      <form action="{$form_action}" method="post">
          {$content}
      </form>
  {else}
      {$content}
  {/if}

WHEN TO CUSTOMIZE:
  - Add plugin-specific wrapper HTML
  - Include JavaScript for validation
  - Add custom CSS classes
  - Modify form structure

---

css/helloworld.css
-----------------
PURPOSE: Plugin-specific styles
LOADED: Via $scriptAdd in helloworld.php
BEST PRACTICES:
  - Use CSS variables for theme compatibility
  - Prefix class names with plugin name
  - Provide responsive styles
  - Include dark mode support

EXAMPLE:
  .hello-message-card {
      background: var(--card-bg, #fff);
      border: 1px solid var(--border-color, #ddd);
  }

js/helloworld.js
---------------
PURPOSE: Plugin-specific JavaScript
LOADED: Via $scriptAdd in helloworld.php
FEATURES:
  - Form validation
  - Interactive UI
  - AJAX operations (optional)
  - Event handling

      // Your code here

5. DATABASE INTEGRATION
================================================================================

NOTE: For FlintmanCMS, the DB_PREFIX constant is set to "flintmancms", so your
actual table names will be: flintmancms_helloworld_messages, etc.

WORKFLOW:
--------
1. Define tables in variable.php $plugin_db_tables array (without prefix)
2. Create schema in sql/install.sql (with flintmancms_ prefix)
3. System creates tables during activation
4. Access via $db object in PHP files (use DB_PREFIX constant)

QUERY PATTERNS:
--------------

SELECT (Single Row):
  $sql = sprintf("SELECT * FROM " . DB_PREFIX . "_table WHERE id=%s",
                 quote_smart($id));
  $result = $db->sql_query($sql);
  $data = $db->sql_fetchrow($result);
  if ($data) {
      echo $data['column'];
  }

SELECT (Multiple Rows):
  $sql = "SELECT * FROM " . DB_PREFIX . "_table ORDER BY date DESC";
  $result = $db->sql_query($sql);
  while ($row = $db->sql_fetchrow($result)) {
      echo $row['column'];
  }

COUNT:
  $count = $db->sql_numrows($result);

INSERT:
  $sql = sprintf("INSERT INTO " . DB_PREFIX . "_table (col1, col2) " .
                 "VALUES (%s, %s)",
                 quote_smart($val1),
                 quote_smart($val2));
  $db->sql_query($sql);

UPDATE:
  $sql = sprintf("UPDATE " . DB_PREFIX . "_table SET col=%s WHERE id=%s",
                 quote_smart($value),
                 quote_smart($id));
  $db->sql_query($sql);

DELETE:
  $sql = sprintf("DELETE FROM " . DB_PREFIX . "_table WHERE id=%s",
                 quote_smart($id));
  $db->sql_query($sql);

ERROR HANDLING:
  if (!$result) {
      $errorMsg = "Database error: " . $db->sql_error();
  }

SECURITY RULES:
--------------
1. ALWAYS use quote_smart() for user input in SQL
2. NEVER directly concatenate user input into SQL
3. Use sprintf() with quote_smart() for parameterized queries
4. Sanitize input with scrub_input() before using

WRONG:
  $sql = "SELECT * FROM table WHERE id=" . $_GET['id'];  // SQL INJECTION!

CORRECT:
  $id = scrub_input($_GET['id']);
  $sql = sprintf("SELECT * FROM table WHERE id=%s", quote_smart($id));

6. FRONTEND DEVELOPMENT
================================================================================

BUILDING USER INTERFACES:
-------------------------

HTML Generation:
  $body = '';
  $body .= '<div class="container">';
  $body .= '<h2>' . htmlspecialchars($title) . '</h2>';
  $body .= '</div>';

Forms:
  $body .= '<form method="POST" action="URL">';
  $body .= '<input type="text" name="field" class="form-control" required>';
  $body .= '<button type="submit" name="submit" class="btn btn-primary">';
  $body .= 'Submit</button>';
  $body .= '</form>';

Links:
  $body .= '<a href="index.php?n=plugins&p=helloworld&action=view&id=' .
           $id . '" class="button">View</a>';

Loops:
  while ($row = $db->sql_fetchrow($result)) {
      $body .= '<div class="card">';
      $body .= htmlspecialchars($row['data']);
      $body .= '</div>';
  }

SECURITY IN OUTPUT:
------------------
ALWAYS use htmlspecialchars() when outputting user data:
  $body .= htmlspecialchars($user_input);

This prevents XSS (Cross-Site Scripting) attacks.

STYLING:
-------
Use CSS classes compatible with CMS themes:
  - .btn, .btn-primary: Buttons
  - .button: Secondary button style
  - .form-control: Input fields
  - .form-group: Form field container

Add plugin-specific styles in css/helloworld.css

SMARTY ASSIGNMENT:
-----------------
  $smarty->assign('text', $page_title);
  $smarty->assign('body', $html_content);

These appear in {$text} and {$body} in templates.

7. ADMIN INTERFACE
================================================================================

AUTHENTICATION:
--------------
Add this at the top of admin.php:
  array_push($page_lvl, 'Admin');
  include(INCLUDES_PATH . 'authentication.php');

This ensures only admins can access.

CRUD OPERATIONS:
---------------

LIST:
Create an array of data, use Report class:
  $items = array();
  while ($row = $db->sql_fetchrow($result)) {
      array_push($items, array(
          'id' => $row['id'],
          'name' => $row['name'],
          'edit' => '<a href="...&action=edit&id=' . $row['id'] . '">Edit</a>',
          'delete' => '<a href="...&action=delete&id=' . $row['id'] . '">Delete</a>'
      ));
  }

  $report->addOutputColumn('id', 'ID', 'left');
  $report->addOutputColumn('name', 'Name', 'left');
  $report->addOutputColumn('edit', '', 'center');
  $report->addOutputColumn('delete', '', 'center');
  $report->display($items);
  $content = $report->showReport();

ADD:
  if (!isset($_POST['submit'])) {
      // Build form
      $form_action = "admin.php?n=plugins&p=helloworld&action=add";
      $content = '<input type="text" name="field" class="form-control">';
      $content .= '<input type="submit" name="submit" value="Save">';
  } else {
      // Process form
      $value = scrub_input($_POST['field']);
      // Insert to database
      header("Location: admin.php?n=plugins&p=helloworld");
      exit;
  }

EDIT:
Similar to ADD, but load existing data first:
  $sql = sprintf("SELECT * FROM table WHERE id=%s", quote_smart($id));
  $result = $db->sql_query($sql);
  $data = $db->sql_fetchrow($result);

  $content = '<input type="text" name="field" value="' .
             htmlspecialchars($data['field']) . '">';

DELETE:
Show confirmation, then delete:
  if (!isset($_POST['submit'])) {
      $content = 'Are you sure?';
      $content .= '<input type="submit" name="submit" value="Delete">';
  } else {
      $sql = sprintf("DELETE FROM table WHERE id=%s", quote_smart($id));
      $db->sql_query($sql);
      header("Location: ...");
      exit;
  }

8. SECURITY BEST PRACTICES
================================================================================

1. FILE ACCESS CONTROL:
   - Check IN_CMS constant at top of every PHP file
   - Add index.html to every directory

   if (!defined('IN_CMS')) {
       die("ERROR - Direct access not permitted");
   }

2. INPUT SANITIZATION:
   - Use scrub_input() for ALL user input
   - Applies to $_GET, $_POST, $_COOKIE

   $id = scrub_input($_GET['id']);

3. SQL INJECTION PREVENTION:
   - Use quote_smart() for SQL parameters
   - Use sprintf() for parameterized queries
   - Never concatenate user input directly

   $sql = sprintf("SELECT * FROM table WHERE id=%s", quote_smart($id));

4. XSS PREVENTION:
   - Use htmlspecialchars() when outputting user data
   - Escapes HTML special characters

   echo htmlspecialchars($user_input);

5. AUTHENTICATION:
   - Check permissions for sensitive operations
   - Use authentication.php include
   - Verify admin status for admin pages

   array_push($page_lvl, 'Admin');
   include(INCLUDES_PATH . 'authentication.php');

6. FORM VALIDATION:
   - Validate on both client (JS) and server (PHP)
   - Check required fields
   - Verify data types and formats
   - Provide clear error messages

7. CSRF PROTECTION:
   - For critical operations, implement CSRF tokens
   - Verify referer for sensitive actions

8. FILE UPLOADS:
   - Validate file types
   - Check file sizes
   - Store outside web root or with random names
   - Never trust uploaded filenames

11. TROUBLESHOOTING
================================================================================

PLUGIN WON'T ACTIVATE:
---------------------
- Check variable.php syntax
- Verify table names match between variable.php and install.sql
- Check SQL syntax in install.sql
- Look for PHP errors in logs
- Ensure database user has CREATE TABLE permissions

NO CONTENT DISPLAYS:
-------------------
- Check if IN_CMS constant blocking access
- Verify authentication permissions
- Check database queries for errors
- Look for PHP errors/warnings
- Verify Smarty variable assignments

CSS/JS NOT LOADING:
------------------
- Check $scriptAdd syntax in main plugin file
- Verify file paths are correct
- Check file permissions
- Clear browser cache
- Check browser console for 404 errors

DATABASE ERRORS:
---------------
- Use $db->sql_error() to see error message
- Check table names include DB_PREFIX
- Verify quote_smart() used for all parameters
- Check SQL syntax
- Ensure fields exist in tables

ADMIN FEATURES NOT WORKING:
--------------------------
- Verify admin authentication included
- Check $form_action is set correctly
- Verify template/page.htm exists
- Check for PHP errors
- Verify $_POST data being received

PERMISSION ERRORS:
-----------------
- Check $page_lvl array configuration
- Verify group permissions in database
- Check authentication.php include
- Verify user's group has access

AJAX OPERATIONS:
---------------
Create separate PHP file for AJAX endpoints:
  ajax.php:
    <?php
    define('IN_CMS', true);
    require_once('../../../common.php');

    if ($_POST['action'] == 'load_data') {
        // Query database
        // Return JSON
        header('Content-Type: application/json');
        echo json_encode($data);
        exit;
    }

JavaScript:
    fetch('plugins/helloworld/ajax.php', {
        method: 'POST',
        body: JSON.stringify({ action: 'load_data' })
    })
    .then(response => response.json())
    .then(data => {
        // Update UI
    });

FILE UPLOADS:
------------
Form:
  enctype="multipart/form-data" in form tag

Processing:
  if (isset($_FILES['file'])) {
      $file = $_FILES['file'];
      $target = "uploads/" . basename($file['name']);

      // Validate
      $allowed = array('jpg', 'jpeg', 'png', 'gif');
      $ext = pathinfo($file['name'], PATHINFO_EXTENSION);

      if (in_array(strtolower($ext), $allowed)) {
          if (move_uploaded_file($file['tmp_name'], $target)) {
              // Success
          }
      }
  }

PAGINATION:
----------
Calculate:
  $per_page = 20;
  $page = isset($_GET['page']) ? (int)$_GET['page'] : 1;
  $offset = ($page - 1) * $per_page;

Query:
  $sql = "SELECT * FROM table LIMIT $offset, $per_page";

Links:
  $total_pages = ceil($total_records / $per_page);
  for ($i = 1; $i <= $total_pages; $i++) {
      echo '<a href="?page=' . $i . '">' . $i . '</a>';
  }

SCHEDULED TASKS:
---------------
Create cron.php in plugin directory:
  <?php
  define('IN_CMS', true);
  require_once('../../common.php');

  // Perform scheduled task
  // Update database, send emails, etc.

Setup cron job:
  0 0 * * * php /path/to/plugins/helloworld/cron.php

MULTI-LANGUAGE:
--------------
Define language constants in language files:
  plugins/helloworld/languages/english/lang.php:
    define('HELLO_GREETING', 'Hello');
    define('HELLO_FAREWELL', 'Goodbye');

Use in code:
  echo HELLO_GREETING;

PLUGIN UPDATES:
--------------
Create sql/update/ directory with versioned SQL files:
  sql/update/1.0.0-to-1.1.0.sql

Check version and run updates:
  $current = get_plugin_version('helloworld');
  if (version_compare($current, '1.1.0', '<')) {
      run_update_sql('1.0.0-to-1.1.0.sql');
      update_plugin_version('helloworld', '1.1.0');
  }
